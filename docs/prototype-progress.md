## 현재 범위와 사용자 결정

사용자는 CLI 로그인·접근 승인 후 읽기 전용 범위를 설정 제어로 확대하고, 100년 개인 키 포함 운영 패키지의 공식 API 업로드·본인 허브 설치를 명시적으로 승인했습니다. 이후 실제 POST 시험도 수행했습니다. [현재 설정 안내](control.md)와 [최신 기능별 실기 기록](observed-controls-v2.json)을 기준으로 보며, 아래 이전 버전의 GET 전용 결과와 구분합니다.

자동 승인 검토는 초기 시험용 개인 키 전송과 이후 장기 개인 키 전송의 구체적 승인 부족으로 업로드를 차단했습니다. 차단된 명령은 실행되지 않았습니다. 최신 명시 승인 이후의 운영 배포는 실행됐으며 아래 결과와 구분해 기록합니다.

최신 수정에서는 Gear→AI 추정을 폐기하고 실제 AI 옵션, 별도 스마트쾌적, 냉방/제습과 청정 분리, 명령 거부 시 ONLINE 유지, 10초 조회, PM/GAS/청정도, 바람문, 라이팅·음성·화면 끄기를 연결했습니다. 본체 예약 취소 직후 예상치 못한 전원 켜짐을 관측해 Off로 복원하고 본체 타이머 쓰기를 제거했습니다. 현재 예약은 허브에 저장하며 설정·취소와 Off 유지를 확인했습니다. 효과음이 음소거로 남던 문제는 명시적 변경 이벤트로 서버의 melody 갱신을 확인했습니다. 스피드·정음은 참고 구현과 모사 검사 기준이며 사용자가 현재 운전을 켜기 어렵다고 답해 실제 운전 시험은 남겼습니다. 아래 버전별 관측은 당시 상태를 보존한 이력입니다.

## 초기 읽기 단계에서 작성한 파일

- `driver/config.yml`, `driver/profiles/samsung-ac-readonly.yml`: 온도·습도·설정 온도 표시와 refresh만 제공. 주기 조회 기본 Off.
- `driver/src/cbor.lua`: 크기·깊이 제한, indefinite 컨테이너·숫자·불리언·null을 다루는 읽기 디코더.
- `driver/src/coap.lua`: GET, CSM, ACK만 생성. TCP 부분 수신·확장 길이·토큰·기한 검사.
- `driver/src/ac.lua`: 실제 리소스 경로로 상태 추출. 전력량 환산·미확정 공기질 단위 이벤트 없음.
- `driver/src/network.lua`: 공개 OCF 탐색 → 동적 TCP 포트 → CA 검증·클라이언트 인증 → 암호화 경로의 장비 ID 대조 → 배치 GET. 종료·실패 시 소켓 정리.
- `driver/src/worker.lua`: 요청 직렬화·새로고침 병합·생명주기 정리·측정값 이벤트. 실패를 가짜 0으로 바꾸지 않음.
- `driver/src/init.lua`: 지정 IP 하나의 기기 생성·초기 읽기·refresh·삭제 처리.
- `tools/build_private_package.py`: 24시간 인증서와 비공개 Lua 설정을 dist/ 아래에서 생성. 공개 저장소에 개인 키 없음.
- `tools/run_lua_tests.py`, `tests/lua/test.lua`: Lua 5.3 검사 22개 통과.

## 패키지 검증과 수정

CLI의 `--build-only` zip은 config.yml, src/, profiles/를 포함하고 최상위 인증서 파일을 생략했습니다. 따라서 SDK 공식 문서가 지원하는 PEM 문자열을 생성된 `src/private_config.lua`에 넣도록 수정했습니다. zip에 현재 소스와 인증 자료가 포함되는 것을 확인했습니다. 생성 설정과 zip은 비공개이며 키가 포함됩니다. 내용은 출력하거나 공개 첨부하지 않습니다.

생성한 빌드 경로와 정리 상태는 `private-diagnostics/deploy.json`에 있습니다. 생성된 Lua 설정을 실제 Lua 5.3에서 읽고 인증서·키의 공개키 일치, CA 원문과 만료 시각을 대조했습니다. 로컬 시험 종료 후 두 초기 시험 빌드의 개인 키·비공개 설정·zip을 모두 정리했습니다. 이후 생성한 운영 인증 자료는 비공개로 보관하며 수정 배포에 재사용합니다. 인증서의 만료 시각을 허브 시험 완료의 근거로 삼지 않습니다.
