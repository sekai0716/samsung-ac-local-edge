# 읽기 전용 Lua 프로토타입

이 문서는 초기 읽기 단계의 검증 기록입니다. 이후 사용자 요청으로 에어컨 표준 profile과 설정 명령을 추가했습니다. **현재 소스의 기능과 검증 결과는 [설정 구현 안내](control.md)를 기준으로 확인합니다.** 아래 22개 검사는 초기 단계의 결과입니다.

초기 읽기 단계에서 Lua 코드, profile, 비공개 패키지 생성 도구를 작성했습니다. Lua 5.3 검사 22개와 동일 Lua 프로토콜 코드의 PC 실기 조회가 통과했습니다. 당시 사용자는 업로드를 거의 완성했을 때만 하도록 지정했고 SmartThings 업로드·허브 설치·허브 SDK 실행은 수행하지 않았습니다. 이후 운영 패키지 업로드와 v3 허브 설치 목록 확인까지 진행했습니다. 최신 상태는 [진행 기록](prototype-progress.md)에 있습니다.

## 초기 읽기 단계의 동작

- 설치 시 지정한 IP 하나의 공개 OCF 식별자와 동적 TCP TLS 포트를 읽습니다.
- 공개 OCF CA로 서버 체인을 검증하고 시험용 클라이언트 인증서를 사용합니다. DNS 호스트명 검증 대신 암호화 경로의 OCF 식별자를 대조합니다.
- CoAP/TCP의 CSM과 GET, UDP의 GET과 필요한 ACK만 보냅니다. 전원·온도·모드·측정 시작·등록을 바꾸는 메서드는 없습니다.
- 배치 응답을 CBOR로 해석해 전원·현재/설정 온도·습도·모드·풍량·먼지·냄새·공기 등급·전력 카운터를 추출합니다.
- 허브 profile은 `temperatureMeasurement`, `relativeHumidityMeasurement`, `refresh`만 사용합니다. 설정 온도는 `desired` component의 온도 측정값으로 표시하는 코드입니다. 앱에 실제 표시되는지는 아직 검증하지 않았습니다.
- 주기 조회는 기본 Off입니다. 초기 1회와 refresh로 조회하며, 켜면 기본 60초 간격으로 동작하도록 구현했습니다. 실패·누락을 꺼짐이나 0으로 표시하지 않습니다.
- 중복 refresh는 병합하고 장비 제거 때 타이머·소켓을 정리합니다. 지연된 결과는 제거된 장비에 발행하지 않습니다.

먼지 단위·센서 최신성·누적 전력량의 kWh 환산은 미확정이므로 해당 항목은 원시 로그 요약으로 남깁니다. 센서 정확도나 장시간 안정성을 확인한 버전은 아닙니다.

## 로컬 검증 재현

기본 Python 검증 환경에 PC Lua 어댑터용 의존성을 추가합니다. Lupa는 허브 패키지 의존성이 아닙니다.

```bash
.venv/bin/pip install -r requirements-lua-pc.txt

# Lupa에 포함된 Lua 5.3으로 검사
.venv/bin/python tools/run_lua_tests.py

# 별도 Lua 5.3 실행기가 있으면 지정 가능
.venv/bin/python tools/run_lua_tests.py --lua /path/to/lua5.3

# 본인 장비에서 승인한 인증 방식의 GET 시험
.venv/bin/python tools/lua_pc_probe.py --host 192.168.1.170 \
  --output private-diagnostics/lua-pc.json
```

이 작업에서는 공식 소스로 빌드한 Lua 5.3.6 실행기와 Lupa의 Lua 5.3에서 모두 검사했습니다. 기본 재현 명령은 Lupa를 사용하므로 전역 Lua 설치가 필요하지 않습니다.

## 비공개 패키지와 추후 허브 시험

현재 `tools/build_private_package.py`는 IP 인자 없이 자동 검색용 운영 인증서와 생성 설정을 `dist/<빌드시각>/`에 만듭니다. 사용자 요청에 따른 유효기간은 36,500일이며 이번 설치본의 만료일은 2126-09-25입니다. 선택적 `--host <IP>`는 추가 검색 후보로만 보존합니다. 설정 파일과 zip에는 개인 키가 들어 있으므로 공개 저장소나 공유 자료로 사용하지 않습니다. 원본 `driver/` 폴더에는 개인 키가 없고, 생성 설정 없이는 설치용 구성이 완성되지 않습니다.

CLI 2.1.1의 `--build-only`로 zip을 만들고 현재 소스·인증 자료가 들어간 것을 확인했습니다. 폴더 최상위의 인증서 파일은 zip에서 빠졌으므로 SDK가 지원하는 PEM 문자열을 생성된 Lua 모듈에 넣었습니다. 이 형식과 CA·클라이언트 인증서 설정은 [공식 SSL API](https://developer.smartthings.com/docs/edge-device-drivers/ssl.html)를 따릅니다. 이후 허브 내부 TLS 전달과 연결 재사용을 반영해 이 허브에서 실제 인증 GET과 ONLINE을 확인했습니다.

초기 시험용 zip과 생성 설정의 개인 키는 로컬 시험 종료 후 정리했습니다. 이후 운영 인증서·키·CA·만료 시각을 검사하고 동일 인증서로 PC의 실제 에어컨 GET을 확인했습니다. 개인 키 포함 패키지의 `api.smartthings.com` 업로드·본인 허브 설치에 대한 사용자 명시 승인을 받은 뒤 소유 전용 채널을 생성해 업로드·설치했습니다. 공개 초대는 만들지 않았고, 운영 설정과 zip은 비공개로 보관합니다.

허브 설치 이후에는 다음을 확인합니다.

1. 운영 패키지 설치·멀티캐스트 검색·LAN 기기 생성에 이어 허브 단독 GET 5회 연속 성공을 확인했습니다. 최신 범위는 [허브 관측 기록](observed-hub.json)에 있습니다.
2. 현재 버전 로그의 `AC_PHASE`를 통해 공개 탐색·TCP·TLS·식별자·배치 GET의 통과 여부 확인.
3. `AC_STATE`, `AC_QUERY_OK`와 실제 기기 상태 API·앱의 측정값 대조. 로그의 이벤트 큐 등록만으로 앱 반영을 완료 처리하지 않음.
4. refresh·IP 변경·연결 실패·장비 제거 때의 동작과 소켓·타이머 정리.

초기 업로드는 개인 키 외부 전송 승인 부족으로 자동 승인 검토에서 거부됐습니다. 이후 장기 운영 인증서와 정확한 전송 대상에 관한 명시 승인을 받은 뒤 업로드가 실행됐습니다.
